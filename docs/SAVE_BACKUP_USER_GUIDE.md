# 存档备份与恢复使用指南

这份说明面向实际使用 HMM 的玩家，不需要了解代码。它解释如何设置备份、什么时候会自动执行、
关闭 HMM 后怎么办，以及怎样安全地恢复存档。

适用范围：当前 Windows x64 版 HMM，游戏适配器为《怪物猎人：世界 冰原》。项目仍处于 Alpha 阶段。
本文描述当前行为，包含首次启用时的补做规则；不是尚未实现的新方案。

## 先记住这六条

1. **备份是留副本，恢复是覆盖当前存档。** 二者风险不同，恢复前一定核对账号和备份时间。
2. **自动计划和后台保护是两件事。** 配置档决定“备份谁、何时备份”；设置里的后台保护决定
   “HMM 完全退出后，谁继续检查和执行”。
3. **每天 08:00 指 Windows 当前时区的 08:00。** 不看界面语言，不固定按北京时间或 UTC 解释。
4. **后台每 15 分钟检查一次，不是每 15 分钟备份一次。** 到期且尚未完成时才需要执行。
5. **首次启用可能立即补做一次。** 即使今天设置的钟点还没到，系统也可能补做最近一个过去的计划。
6. **关机期间不能备份。** 已启用正常后台保护时，下次登录同一个 Windows 账号后可以补做，
   无需手动打开 HMM；补的是执行时的存档，不是过去时刻的快照。

## 几个名称分别指什么

| 名称 | 通俗解释 |
| --- | --- |
| 存档目录 | 游戏当前正在使用的存档所在文件夹，也就是备份的来源 |
| 备份目录 | HMM 存放历史副本的位置，不应与存档目录混在一起 |
| 存档备份配置档 | 一套独立的存档目录、备份位置、自动计划和保留设置 |
| 后台保护 | 由 Windows 计划任务启动独立备份程序，让 HMM 主界面不运行时仍可检查备份 |
| 恢复前安全备份 | 恢复旧进度之前，先给当前进度留的一份保护点 |

配置档不是游戏里的“角色槽位”，也不是一套 Mod 列表。HMM 对所选存档目录做备份，
不负责从游戏存档内部挑出某一个角色。切换存档配置档不会切换已安装的 Mod。

## 第一次使用

### 1. 确认游戏和存档账号

先完成游戏目录配置，再在存档相关页面选择要管理的配置档。

优先使用存档目录自动发现功能。发现多个 Steam 账号候选时，核对账号和目录提示，
确认真正要备份的那个账号；没有合适候选时再手动选择存档目录。

注意：游戏安装目录通常不是存档目录。不要因为找到了游戏 EXE，就把整个游戏安装文件夹当作存档来源。

### 2. 多账号分别建立配置档

例如，为账号 A 使用默认配置档，再为账号 B 新建一个配置档，各自确认自己的存档目录。
可以用容易辨认的名称，但名称本身不会改变目录，也不会把账号 A 的存档转换成账号 B 的存档。

后台程序会检查所有已保存自动计划的配置档，**不是只检查界面当前选中的一个**。
切换活动配置档不等于停用其他配置档的自动备份；不想继续自动备份某个配置档时，把它改为手动并保存。

### 3. 确认备份位置

第一次使用可以保持默认备份目录。需要放到其他磁盘时，选择一个稳定、可写且空间充足的位置。

不要把备份目录设成存档目录本身，也不要让两者互相包含。否则既容易混淆原件和副本，
也可能造成“备份里再套备份”的问题；应用会拒绝不安全的目录关系。

### 4. 保存设置，先做一次手动备份

目录、计划等配置档设置修改后，需要点击页面的保存按钮。时间选择框里的“确定”只是结束选时，
不要把它当成已经保存了整个配置档。

建议先退出游戏，再执行一次手动备份。看到备份历史里出现“已完成”的记录后，
再通过“打开文件夹”等入口确认能找到备份。不要只凭按钮按过、开关亮了，就认为已经有可用副本。

### 5. 设置自动计划

在相应配置档中选择每日或每周计划，设好时间；每周计划还需要选择星期。保存后查看自动备份运行期信息。

自动计划只规定节奏，不是“存档一变化就马上备份”。手动备份仍可按需使用。

### 6. 需要退出后继续工作，再开启后台保护

打开设置中的 **“退出后继续保护自动备份”**，等待状态确认已受保护。
这个全局开关不会把手动配置档变成自动配置档；两处设置都要符合你的用途。

开启或修复失败时，先看提示解决问题，不要通过删除系统任务、强杀后台程序或改数据库来让界面变绿。

## 备份保存在哪里

默认情况下，HMM 使用系统文档目录下的专用文件夹：

```text
<系统文档目录>/HelsincyModManager/saves/<游戏标识>/profile-<配置档内部标识>/
```

自定义位置时，会在你选择的根目录里建立同样的受控结构：

```text
<你选择的备份根目录>/HelsincyModManager/saves/<游戏标识>/profile-<配置档内部标识>/
```

这些尖括号表示说明用的占位符，不是让你照着创建同名文件夹。系统文档目录可能被 Windows 重定向，
特殊环境下也有回退位置，因此以应用实际解析的位置为准；最方便的定位方式是使用页面中的“打开文件夹”。
默认模式会定位到当前配置档子目录；自定义模式可能先打开你选的根目录，再进入上述子目录即可。

普通手动和自动备份通常有配套的两个文件：

- `.zip`：保存存档内容的压缩包。
- `.manifest.json`：记录这份备份的身份、文件清单和校验信息，可理解为它的“说明与校验清单”。

恢复前安全备份放在该配置档下独立的 `pre-restore/` 子目录。

不要单独改名、编辑或删除配套清单，也不要认为把任意 ZIP 放进目录就会自动变成 HMM 可恢复的历史记录。
应用恢复依赖备份内容、配套清单和历史记录共同校验。更换备份位置也不等于自动迁移了已有备份，
移动或清理旧目录前应先核对历史记录的可用性。

本地备份不能抵御整个磁盘损坏。重要进度建议另外保留在独立介质上；复制副本时保留配套清单，
但不要把“复制了文件”理解成已经完成跨电脑导入或恢复验证。

## 自动计划究竟怎样执行

### 每日和每周不是倒计时

“每日 08:00”表示每天当地时间的一个计划点，不是从你点击保存起每隔 24 小时。
“每周一、三、五 08:00”表示在这些当地星期的对应钟点到期。

每日计划没有固定的单次执行日期。“下次计划”显示的日期由后端根据当前时间和规则计算。

到期时，还要等客户端或后台程序实际检查，并通过游戏状态、目录和任务占用等检查，才会开始备份。
**计划时间是到期时间，不是精确到秒的完成承诺。**

### 每 15 分钟检查，不代表每 15 分钟产生一个包

Windows 后台任务约每 15 分钟运行一次检查；用户登录时还有延迟 1 分钟的触发。
启用后台保护时也会尝试首次启动检查，不能认为开启后一定要等满 15 分钟才有动作。

以每日 08:00 为例：

- 07:55 检查时，如果过去的计划已经完成，就不需要备份。
- 08:00 到期后，假设下一次实际检查在 08:08，备份就可能在 08:08 开始。
- 这次完成后，后续检查不会仅仅因为又过了 15 分钟，就为同一个已完成计划再备份。

系统调度、睡眠、游戏运行、目录不可用或其他任务占用还可能继续推迟执行。
不要把 15 分钟当作所有异常情况下的最长延迟。

### 首次启用，为什么没到今天的时间也备份了

这是当前保留的“追赶”规则：程序查找最近一个已经过去的计划点，再看有没有成功自动备份覆盖它。
**如果这个配置档没有成功的自动备份历史，过去那个计划点也会被视为待补做，
即使你当时还没有启用这项计划。**

例如，今天 07:50 第一次启用每日 08:00：

1. 最近一个过去的 08:00 是昨天的 08:00。
2. 没有自动备份历史，程序可能在今天 07:50 之后先补做一次。
3. 今天 08:00 又是一个新的计划点，到期后仍可能再备份一次。

因此，首次启用不是“保证等到下一个未来时间才第一次备份”。每周计划同样可能补做最近一个已经过去的所选星期。
补做只保存执行时能读取到的存档，并不能找回昨天没有保存过的快照。

手动备份不算自动计划已经完成：刚刚手动备份成功，再首次启用自动计划，仍可能出现上述补做。

### 修改时间，为什么同一天又备份一次

修改并保存后，程序按新计划重新判断是否到期。它不是“无论怎样修改，每个自然日最多一个自动备份”。

例如，以下是一组可能的过程，实际执行时刻取决于检查时机：

| 操作或时刻 | 当前规则下的结果 |
| --- | --- |
| 01:05 首次保存每日 01:10，没有自动备份历史 | 可能先补做最近的过去窗口 |
| 01:10 到期，随后检查 | 为 01:10 这个计划执行自动备份 |
| 01:13 改为每日 01:15 并保存 | 新计划开始参与后续判断 |
| 01:15 到期，随后检查 | 01:10 那次备份早于新的到期点，因此还可能再执行一次 |

如果把计划改到当前时间之前，且最近的成功自动备份没有覆盖新计划的过去窗口，也可能触发补做。
只滚动时间选择器、没有保存配置档，不会把每一个中间数值都作为已生效计划执行。

### “计划尚未到期”与历史里有自动备份矛盾吗

不矛盾。状态描述的是当前检查结果，不是在否认历史。

例如，今天 08:08 已完成今天的 08:00 计划，到了 08:20，页面可以显示“计划尚未到期”，
并把“下次计划”显示为明天 08:00。过去已经成功，下一轮还没到，是可以同时成立的。

## 时区和文件名中的时间

### 计划跟随操作系统时区

设置每日 08:00：北京时间的电脑按北京 08:00 判断，纽约时区的电脑按纽约 08:00 判断，
柏林时区的电脑按柏林 08:00 判断。切换 HMM 的中文、英文或日文界面不会改变计划的时区。

请检查 Windows 的日期、时间和时区是否正确。出行后如果系统时区变化，后续检查会按新时区重新计算，
不是永久保留设置当天的 UTC 偏移；当前没有为单个配置档指定固定时区的功能。

夏令时也按系统规则处理：春季跳时让某个钟点不存在时，顺延到第一个有效分钟；秋季回拨让同一个
钟点出现两次时，采用第一次，不因为时钟再次经过同一钟点而重复完成同一个计划。
跨时区移动会重新计算计划，不保证仍然按出发地的自然日只执行一次。

### 压缩包文件名仍使用 UTC

文件名时间与计划时间的用途不同：计划使用当地时间，文件名使用统一的 UTC 时间，方便稳定排序。

例如文件名开头是 `20260920-172249`，表示 UTC 的 9 月 20 日 17:22:49。
换算成北京时间是 **9 月 21 日 01:22:49**，不是“昨天备份”，也不是把计划设置到了下午。

判断是否提前、延后或重复时，应把文件名、Windows 时间和自己的操作记录换到同一个时区再比较。
不要只看文件名里的日期，或把“7 分钟前”当成计划本身的钟点。

## 关闭软件与开关机后的行为

以下都以配置档已保存自动计划、目录可用为前提：

| 当前情况 | 未开启后台保护 | 后台保护已开启且系统任务正常 |
| --- | --- | --- |
| HMM 主程序仍在运行 | 客户端可检查和执行自动计划 | 可检查和执行，已有去重和任务占用保护 |
| HMM 收起到托盘，进程仍在 | 客户端仍可工作 | 仍可工作 |
| HMM 完全退出，用户仍登录 | 没有退出后的自动执行保障 | Windows 可启动独立备份程序，无需打开主界面 |
| 电脑开机，但尚未登录对应 Windows 账号 | 不能依靠 HMM 执行 | 用户级后台任务也不能据此获得运行保障 |
| 关机、休眠或睡眠期间 | 不执行 | 不执行；当前任务不会主动唤醒电脑来备份 |

关闭窗口不一定等于完全退出，请以自己的关闭行为设置和托盘状态为准。真正退出时，若 HMM 提示
后台保护尚未验证、不可用或有恢复任务进行中，应先处理提示，不要强杀进程绕过保护。

### 08:00 前关机，09:00 才开机，还没打开 HMM

只要关机前已经启用正常的后台保护，开机后登录的是启用它的同一个 Windows 账号：

1. Windows 根据已注册任务启动独立后台程序；登录触发配置了约 1 分钟延迟，实际时间受系统调度影响。
2. 后台程序读取已经保存的计划，发现今天 08:00 尚未有成功自动备份覆盖。
3. 游戏状态和目录等检查通过后，补做一次备份，不要求先打开 HMM。
4. 这次成功后，等待下一个计划点；之后打开 HMM 可以查看记录。

如果直到 10:00 才登录，就不能按 09:00 已开机来推算备份一定完成。只启动电脑和登录用户是两件事。

如果错过了好几天，通常只补做一次当前存档，不会补出多份假装属于过去每天的不同存档。
如果登录后已启动游戏，自动备份会在游戏运行中或运行状态不明时延后，等待后续检查。

## 怎样判断后台保护正常

不要只看开关是否打开，还要看状态说明和备份结果。

| 状态含义 | 应当怎样理解 |
| --- | --- |
| 未启用后台保护 | 不能承诺 HMM 完全退出后仍自动备份 |
| 正在验证、启动中 | 已发起启用，但尚未确认后台程序的有效运行回报，不等于已受保护 |
| 已受后台保护、退出后受保护 | 已确认系统任务匹配且近期有有效后台运行回报；仍受开机、登录、目录和游戏状态等条件限制 |
| 启用失败、后台不健康、权限或配置异常 | 先按提示处理，不要继续假定退出后的备份可靠 |

后台的“运行回报”可以理解为它向 HMM 报了一次平安，不等于这次一定创建了新备份。
没到期时，后台可以正常检查并更新健康状态，而不产生新包。

“最近检查：刚刚”也不等于“刚刚备份成功”。需要同时查看最近成功备份和历史中的完成记录。

点击“立即检查”是重新检查计划，不是无条件强制备份：到期且满足条件时可能执行，
未到期或被安全条件阻挡时不会强行创建备份。要明确保存当前进度，应使用手动备份入口。

不想继续后台运行时，从 HMM 设置中关闭后台保护；只想停止某一个配置档的自动计划时，
将那个配置档改为手动并保存。不要自行编辑任务参数或删除安装目录中的后台 EXE。

## 备份历史与保留策略

### 看什么才算成功

重点看备份类型、时间和状态。手动备份、自动备份、恢复前安全备份的用途不同。
“已完成”记录才是正常恢复候选；缺失、无效、已整理或清理未完成的记录，不能仅凭文件名看起来正常就强行恢复。

可以添加备注，例如“安装某个 Mod 前”或“主线完成后”，便于以后挑选。
备注是说明，不会修改备份里的游戏进度。

### 数量、天数、空间分别限制什么

| 设置 | 例子 | 含义 |
| --- | --- | --- |
| 保留数量 | 10 | 普通备份超过数量限制时，较旧的会成为整理候选 |
| 保留天数 | 30 | 超过约 30 天的普通备份会成为整理候选，不是“每 30 天备份一次” |
| 空间上限（MiB） | 1024 | 给该配置档的已知备份压缩包设置约 1 GiB 的总空间预算 |
| 任一项为 0 | 0 | 只是不限制对应维度，不是停用备份，也不是保留零份 |

新配置档和主动重置保留设置时，三项默认都是不限制。多个非零限制会一起参与整理，
不是“数量没超就一定不会删”：天数或空间超限，同样可能让旧备份进入候选。

需要知道的保护规则：

- 普通手动和自动备份会一起参与普通整理，不是只删自动备份。
- 最新的一份普通已完成备份会保留，避免普通整理把可用普通副本全部删空。
- 所有恢复前安全备份不参与普通自动整理，但它们仍占磁盘空间，也会计入空间预算事实。
- 如果受保护的文件本身已超过预算，应用可能显示无法满足预算，而不是突破保护规则继续删除。
- HMM 的预算不是整个磁盘或目录所有文件的大小统计；它主要依据已知备份压缩包，未知文件等另当别论。

普通新备份完成后会执行相应整理，也可以在备份中心使用“立即整理”。显式整理会要求确认，
可能永久删除旧备份及其配套清单，不能假定会进回收站；重要副本请提前独立保留。

看到“清理未完成”“部分完成”或“被阻止”时，不要当成已经释放了全部空间，也不要手工删数据库记录。
先检查磁盘、权限和文件是否被占用，再按提示重试或反馈问题。新备份完成与旧备份整理失败可以同时发生。

## 安全地恢复存档

恢复会把所选旧进度写回当前配置档的存档位置，不是简单地“打开 ZIP 看看”。

建议按以下顺序操作：

1. **退出游戏。** 恢复时不要让游戏继续写存档；游戏运行状态不明时也不能强行继续。
2. **核对配置档、账号和目标目录。** 特别是多 Steam 账号、近期换过存档目录的情况。
3. **选择正确的已完成备份，查看恢复预览。** 不仅看备注，还要看时间、类型和提示。
4. **保留默认开启的“恢复前安全备份”。** 它先保存当前进度，再提交所选旧备份的恢复。
5. **阅读风险提示并确认，等待任务终态。** 不要在提交、回滚或收尾过程中强制退出应用。
6. **确认任务成功，再进入游戏核对进度。** HMM 的文件校验通过不等于它能理解并证明每个角色的游戏内状态。

HMM 会核对压缩包、配套清单和备份身份等信息。文件被改动、损坏、不属于当前恢复范围、
目标目录不安全或有任务冲突时，会拒绝继续，而不是跳过检查强行写入。

如果主动关闭恢复前安全备份，会失去这次恢复前新建的保护点，并需要额外确认风险。
一般不建议为了省一点空间而关闭它。

出现“已回滚”时，按结果提示核对；出现“需要人工处理”“恢复证据需要检查”等状态时，
停止继续覆盖、清理或反复恢复，保留现场并联系支持。不要自行删除临时目录、回滚目录或相关记录来消除提示。

Steam 云同步与 HMM 的本地备份是两套机制。HMM 不负责裁决 Steam 的云存档冲突；
恢复后遇到云同步选择时，应核对账号和想保留的进度，不要直接认定时间较新的那份就是正确的。

## 常见问题

### 我只开了每日备份，为什么退出 HMM 后没有备份

每日计划不等于后台保护。完全退出后需要设置中的全局后台保护已开启且正常。
如果没有开启，只能在客户端有机会运行时检查和补做，不能要求已关闭的客户端自行执行。

### 为什么第一次刚设置好就出现自动备份

先看本指南的首次启用规则。没有成功自动备份历史时，当前版本可能补做最近的过去计划。
如果此后在没有改计划的情况下，同一个已经完成的窗口仍反复生成自动备份，再记录时间并反馈。

### 我刚手动备份过，为什么又自动备份

手动备份不替代自动窗口的成功记录。两种类型可以分别出现，这与重复完成同一个自动窗口不是一回事。

### 开关一直开着，为什么还是不执行

按顺序检查：配置档是否已保存为每日/每周、后台状态是否健康、是否已登录原 Windows 账号、
游戏是否仍在运行、存档与备份磁盘是否在线且可读写、是否有其他备份或恢复任务占用。
到期不代表绕过这些条件，重新打开 HMM 后应查看具体状态和错误提示。

### 换了 Windows 账号，后台任务还能直接沿用吗

当前后台保护是用户级任务，不能把另一个账号下的启用状态当成当前账号的保障。
登录另一个账号后，应在该账号的 HMM 中重新确认设置、目录权限和后台保护状态。

### 改了时间或时区，要按哪一个时间看结果

以已经保存的计划和 Windows 当前时区为准。记录修改前后的值和保存时间，
再对照同一时区下的备份创建时间；不能把修改前产生的记录全部归到新计划。

### 自动备份会修改当前存档吗

创建备份是读取存档、生成副本，不是把旧进度写回去。保留策略可能整理旧备份，
但不要把这种整理与“恢复覆盖当前存档”混为一谈。

### 软件启动就提示缺少 WebView2，还没进入备份页面

WebView2 是 Windows 版主界面的运行依赖，与备份计划是否到期无关。如果安装器没有成功准备它，
请使用[微软官方下载页](https://developer.microsoft.com/microsoft-edge/webview2/)中的运行时安装程序，
选择适合 Windows 架构的版本；不要下载散装 DLL，也不要把 SDK 当成运行时。
在 Windows 沙盒里运行 HMM，就要让运行时在沙盒内可用，宿主机安装不等于沙盒已安装。

如果必须手动补装才能启动，应在反馈中说明，不能因此认定 HMM 安装器的自动依赖安装流程已经验证通过。

## 怎样验证设置真的有效

日常使用先确认一次手动备份成功，再开启自动计划和后台保护。
需要专门验证退出后的行为时，建议在一次性 Windows 测试账号或虚拟机中用人工文件测试，
不要拿唯一一份真实进度练习恢复或清理。

一组实用的观察步骤：

1. 保持电脑开机和用户登录，确认测试配置档的手动备份成功。
2. 开启后台保护，等待已受保护；保存一个即将到期的每日时间，记录保存时间和已有历史。
3. 注意首次启用可能先补做一次，先把这条与随后计划到期的备份区分开。
4. 完全退出 HMM，保持测试环境打开、不睡眠，观察至少两个后台检查周期，例如 35–40 分钟。
5. 重新打开 HMM，核对备份创建时间是否在“退出之后、重新打开之前”。
   重新打开可能触发追赶，不能把重新打开之后才生成的备份当成退出期间已完成。
6. 同时检查备份成功记录和后台健康状态。没有黑窗口，不等于任务一定执行成功。

需要验证恢复、整理、注销或卸载时，放在依赖这些备份和设置的观察完成之后，避免先把测试场景删掉。
Windows 沙盒关闭后会丢弃其中的安装和配置，不能用“关闭沙盒再新开”冒充持久系统的关机后补做验收。
关机重启场景需要能保留安装、账号和计划任务的测试系统。

## 出问题时怎样反馈

有助于排查的信息是：应用版本、Windows 版本和时区、是否开启后台保护、计划的旧值与新值、
点击保存的时间、退出和重新打开的时间、预期与实际备份时间，以及界面上的错误码或状态。

需要日志时，优先使用应用诊断导出入口。公开反馈前检查并遮挡用户名、完整路径、Steam ID 等信息；
不要公开上传真实存档、整个应用数据库或系统任务 XML。仅靠“刚刚”“几分钟前”有时不足以还原顺序，
记录同一时区下的具体时间更容易定位。
