# MHW 装备重定向的资源保留策略

MHW 的默认重定向先盘点整个包，再按装备源修改能明确定位的资源路径。文件不在已知模型命名表中，
不再是拒绝整包或漏掉该文件的理由。此策略仅作用于 MHW。

## 文件归属与最终去向

所有输入先验证相对路径和文件身份，再剥离包装目录；不能把含父级穿越的路径截成合法路径。
已识别的装备根目录段按游戏规范统一大小写，文件名、作者目录和扩展名保留原拼写。
同一包里的大小写碰撞仍拒绝，不合并、不选一个覆盖另一个。

每个文件必须归入以下一种情况：

| 类型 | 处理 |
| --- | --- |
| 源装备内可明确映射的非贴图资源 | 按同类目标的资源编号改目录和文件名，保留内容 |
| `.tex` 贴图 | 保留原路径和原内容，维持材质对原位置的引用 |
| 未知模型名、无法唯一映射的附加文件 | 保留原路径并安装，计划给出 `unmapped_resources_kept` 提示 |
| 游戏根内的包级声音、特效、作者资源等 | 由一个源计划承载，整个包只装一次 |
| 其他装备源的资源 | 由该源自己的计划处理，不能因选择另一件装备而静默漏装 |
| 可执行／脚本拒绝清单命中的文件 | 明确排除，并记录排除数量 |
| 游戏根外的说明和预览资源 | 不进入游戏安装计划 |

纯装备目标切换会保留当前 Mod 已可信安装的政策排除附件，例如普通安装时包含的插件 DLL。
后端核对同 revision 的文件身份、原路径、层、内容摘要和实际文件，再将它们纳入完整候选的
`Retained` 集合；附件不重新写入，原备份引用继续有效。迁出装备的旧模型路径仍正常清理。
未安装附件不会补装，也不接管其他来源的文件。版本升级和卸载不采用这条保留规则。

adapter 提供完整政策盘点时，每个既有文件 ID 必须出现在候选或明确排除事实中；原包文件缺失
不能被解释成可删除的旧文件。候选读取按文件 ID 显式选择暂存或原包，暂存读取失败不回退猜测。
预览展示保留附件数和本次未包含数；首次定向安装也提示政策排除的插件／工具可能影响功能。

一张出现在武器树里的共享贴图不会决定整个包的类型。武器和防具独立发现，允许同包存在多个源。
源内的单个 MOD3、单个 MRL3 和不成对副件均可参与路径重定向，不要求先完成二进制配对分析。
默认流程不调用二进制内容 reader，也不改变 MOD3/MRL3 内容。目标不同而没有任何资源路径能改变时，
返回 `weapon_no_relocatable_resources`，避免把原样安装描述成成功重定向。

保留未知资源保证它们不会丢失；这不保证每一种作者自定义结构都能在新装备上产生完整效果。
界面应显示保留提示，不应承诺某个兼容百分比。

## 文件处置预览与当前目标重新应用

adapter 为每个进入重定向盘点的文件提供明确处置及原因，并核对明细完整覆盖动作和政策排除事实。
同一文件不能重复、凭空出现或在明细里改成另一路径。移动、作者原位、包级配套、未包含插件候选和
策略排除分开表示；app 完成安装事实核验后，再补当前管理位置、最终文件变化及已安装附件保留。
说明／预览图等未进入游戏计划的资源不伪装成装备动作。前端只展示相对路径和原因，不重建路径规则。

“重新应用当前目标”从已安装 revision 和完整目标集合重建候选，保留绑定身份、来源、实际目标和
文件层级。存在实际文件差异时沿用真正重装事务；没有差异则返回 `no_changes`，无 token，不写游戏
文件或清单，也不为旧无绑定安装单独回填元数据。已安装附件继续保留，未包含附件不会因此补装。
旧无绑定安装仍须先通过原位证据，普通同目标切换的拒绝条件保持不变。

暂存读取器记录实际用于生成候选的原始字节摘要，与转换后内容摘要区分。两者参与预览和批量摘要，
提交时复核参与本次产出的原包文件及游戏文件，源缺失／变化、旧 token、目标变化均不能提交。
持久事务保存明确的重新应用意图，重启恢复仍消费目标快照及原清单，不依赖重新读取原包。
回滚会逐项移除已恢复目标，因此“必须有变更”在 Planned／Committing 校验，不阻止恢复阶段清空目标。

本入口不升级武器目录映射、不新增插件选择或猎虫类型；后续规则更新可通过该入口应用到当前目标。

## 原位安装与名称缺失

“保持作者设定的替换对象”由后端按源资源身份解析。若名称表中没有这个源，但资源语法合法，
MHW adapter 可建立仅限该源原位安装的稳定身份；它不会出现在目标目录中，也不能作为其他源的目标。
名称 DTO 保持空表，界面显示“名称未知”和实际编号，不生成虚构的装备名称。

武器选择仍按所有已知名称展开。共享模型的名称可分别搜索和选择，提交使用同一个真实目标 ID，
界面同时解释共享模型的影响范围。前端不解析武器编号、资源路径或目录家族。

普通安装在规划前确定导入 revision，计划、读取原包和最终清单共用该版本。普通首次安装、普通新版本
重装及批量安装按最终 InstallPlan 实际包含的文件建立全部可识别源的原位绑定；未选中的源不产生绑定。
该过程不调用重定向改名或文件排除流水线，不改变普通安装的文件集合、内容或插件政策，也不填造
transformer／排除计数。多武器、多防具和混合包安装后可直接切换目标，后续新导入版本不替代已安装版本。
来源分析或原位身份不可确认时，普通安装仍沿用已验证的文件计划，只为能够确认的源保存记录；不能
为了补元数据而拒绝原本合法的包，也不能伪造缺失绑定。实际重定向继续执行既有来源校验。

批量计划的完整绑定集合进入 facts digest。既有单绑定字段只在恰好一个源时使用，多源记录由后端在
执行时按同一规则重建；自动生成的原位记录不授予绕过未完成重定向选择意图的权限。

## 旧原位安装的来源恢复

没有任何装备绑定的旧安装，只有在原包、可信清单和实际文件全部吻合时，才可在切换目标时恢复来源。
核对完整文件集合、package file identity、目标路径、layer、字节数和 SHA-256；接管记录、文件缺失／
被修改、摘要缺失、原包不可读、布局不一致及其他 Mod 的目标归属重叠均阻断。

清单已明确记录 revision 时使用该版本，即使库中后来导入了新版本。旧条目缺少 revision 时，只接受
该 Mod 唯一可用的导入版本，并要求它与已有 origin provenance 一致且通过完整文件验证；有多个版本
时不会猜测 origin 或最新显示版本。替换目标页面的来源与兼容目标也按该 profile 的已记录版本查询。
这些只读展示不等于通过原位验证；缺少绑定时界面说明将在预览中核实。

预览不改写清单。后端生成 `OriginalInstallEvidence`，把原位绑定和文件事实纳入预览 token 与批量
事实摘要；前端不能提交恢复证据或确认标志来绕过验证。确认切换后，提交阶段复核原包内容、版本、
原清单、目标文件和备份。新绑定与游戏文件通过同一个重装事务提交，不另做一次元数据写入。

事务保存原样的 `pre_reinstall_manifest` 和可选的版本化原位证据。证据只帮助验证来源连续性，不把
合成绑定提前塞进旧清单。失败回滚恢复原文件和未补绑定的原清单；中断后通过现有重装恢复扫描与
`ReconcileReinstall` 流程消费持久证据。旧事务缺少此字段仍可读取，现有单源／多源限制继续生效。

恢复只随当前 Mod 的目标切换预览触发，不在启动或卡片 hover 时全库扫描或批量回填，也不提供
纯元数据的强制恢复入口。无法证明原位布局时，界面说明原因并保留卸载后重新定向安装的路径。

## 多源首次安装和再次切换

详情面板只在打开替换目标 Tab 时查询配置；单源面板保留原操作方式，多源面板为每个装备源显示名称、
编号和独立选择。首次安装默认保留作者设定的对象；已安装包默认带入每个源实际安装的目标。只调整一项
不会重置其他项。界面发送完整的源选择集合，然后生成一份预览和一次安装任务。

首次安装仍要求恢复状态为 `not_installed`。原有 `SoleSource` API 遇到多源仍拒绝；新入口显式携带
`PerSlot` 意图，调用现有 staging、任务、准入、写锁和提交机制。失败或取消时的 Mod 级选择意图屏障
继续保留，防止随后走普通安装时误装原始目标。该屏障不等价于持久化整组 UI 选择。

再次切换从可信 manifest 的已安装 revision 重建候选，不能借机切换到新导入的 revision。
请求必须覆盖当前分析的全部源，重复源、缺少源、来源不符及整组目标未改变均拒绝。
多个来源可以指向同一目标，例如刀身与刀鞘、身体与头部由不同源提供；是否冲突由规范化后的最终文件
路径决定。每源绑定独立保留，重启后仍可只调整其中一源，其他来源和包级资源保持完整。
计划与跨 Mod 检查共用 Windows 路径比较键：大小写、Unicode 规范化及尾随点／空格等价的目标不能
当成两个独立文件。比较键不改写保存的路径拼写；不同 layer 也不能放行不同拼写的等价目标。
重装时，候选与已有受管文件仅大小写不同时沿用清单中的路径拼写，避免把同一个文件当成新增和删除。
旧清单含歧义别名或只有 Unicode 规范化键相同、实际拼写不同的布局继续阻断，不据比较键猜测文件归属。
已有绑定保持原 ID、创建时间和 source 身份；新发现的源由后端生成确定性绑定。新的多源校验要求所有
已有源继续存在，并至少有一个实际目标变化或新增源，原有单源校验保持独立。

预览返回的 token 绑定整份候选；更换选择后必须重新预览。前端按任务 ID 处理事件，丢弃过期查询和
预览，写入完成后重新读取安装事实；刷新失败只允许重试刷新，不允许重复写入。

## 安装安全与旧事实兼容

所有游戏写入继续经过 `InstallPlan`、最终路径冲突检查、backup、manifest 和 rollback/recovery。
全部文件发生冲突时，预览仍保留冲突 provider 和绑定事实；执行器在任何写入前拒绝该计划，manifest
仍要求绑定对应实际安装条目。目标级占用提示允许继续生成预览，只有真实文件冲突才阻止安装。
暂存后重建计划必须保留预览发现的跨 Mod 冲突。重装恢复事务的绑定唯一性与 manifest 一致，按
`(Mod, source)` 校验，不能误把同 Mod 的第二件装备当成重复绑定；重复 source 和重复 binding ID 仍拒绝。
同 game/profile 写入串行，取消屏障、提交前状态检查及 token 校验继续复用原任务服务。

原包只读。首次安装的各源 staging 分开路由，包级资源仅承载一次；重装候选使用单次操作拥有的 staging。
预览完成、任务成功、失败或取消后均清理自己拥有的暂存产物。卸载以 manifest 的实际安装条目为准，
恢复被覆盖的旧目标并保留不属于此 Mod 的文件。

默认策略事实为 `mhw.equipment / path-only-resource-preserving / 1`，transformer 集合为空。
旧材质迁移 adapter 以 `MhwMaterialReplacementAdapter` 保留，原二进制解析、转换器和版本仍可读取、验证；
这些能力不再作为默认资源路径重定向的门槛。无内容转换的 facts 不填造旧 transformer 的部件／文件计数，
实际文件数以 InstallPlan/actions 和 manifest 为准。

## 验证

测试只使用人工资源和临时目录：

- `hmm-games-mhw/tests/retarget_package_preservation.rs` 覆盖贴图、单独模型／材质、未知附加资源、混合装备、
  包级资源、未知名称原位身份、无法移动时拒绝及危险路径／可执行文件边界。
- `hmm-core/src/equipment_reinstall.rs` 覆盖来源保持、缺失源、重复身份、同目标组合及新源的绑定约束。
- Runtime 的 `core_mod_lifecycle_tests::equipment` 验证实际文件内容、重启后的多源切换、卸载恢复 baseline、
  stale token、跨 Mod 冲突和 manifest 故障时的整体回滚。
- `runtime_equipment_composition_tests.rs` 验证刀身／刀鞘与身体／头部的同目标组合、独立绑定、
  重启后只移动一源以及完整卸载恢复。
- `runtime_equipment_canonical_tests.rs` 和 `runtime_equipment_batch_tests.rs` 覆盖普通安装／重装／批量
  来源记录、文件集合一致性、新版本导入后的旧版本切换、预览过期与卸载恢复。
- `original_install_tests.rs` 与 `runtime_equipment_origin*_tests.rs` 覆盖旧原位证明、拒绝伪造／不完整
  事实、提交前原包复核、正常切换、取消、清单失败回滚和中断后恢复原清单。
- `runtime_equipment_attachment*_tests.rs` 覆盖附件保留、备份归属、单源／多源／旧记录、未安装文件
  不补装、源与目标变化、取消、中断恢复、批量事实一致性及版本升级仍按实际差异清理。
- `equipmentRetargetBehavior.test.mjs` 验证全源请求、共享模型名称、未调整目标保留、乱序预览、提前完成事件、
  监听失败、取消和刷新失败重试。

人工验收应额外确认进入游戏后的模型、材质、声音和特效。自动测试不能代替游戏内兼容性验收。
