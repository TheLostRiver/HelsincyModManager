# 构建发布与脚本说明

本文档规划 Helsincy Mod Manager 后续的本地开发、构建、打包和发布脚本。当前项目仍处于脚手架前阶段，本文档中的命令分为“计划命令”和“当前可用命令”。

## 目标

- 为开发、验证、打包、发布提供统一入口。
- 避免每个协作者或 agent 自行发明脚本。
- 让 CI、本地验证和发布流程共享同一套检查逻辑。
- 明确脚本职责，避免把构建、测试、发布逻辑混在一起。

## 计划中的技术栈

- Tauri 2
- React + TypeScript
- Rust workspace
- SQLite
- pnpm
- GitHub Actions

## 当前可用命令

脚手架创建前，当前仅能执行仓库和文档层面的检查：

```powershell
git status --short --branch
git diff --check
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\verify.ps1
```

如果后续新增脚本，应优先通过统一入口调用，而不是让文档散落多个命令版本。

## 计划中的本地开发命令

脚手架落地后，计划提供：

```bash
pnpm install
pnpm run dev
pnpm run build
pnpm run lint
pnpm run test
pnpm run tauri dev
pnpm run tauri build
```

具体命令名称以最终 `package.json` 为准。若命令名称发生变化，必须同步更新本文档和 `docs/TESTING.md`。

## 计划中的 Rust 命令

Rust workspace 落地后，计划支持：

```bash
cargo fmt --all -- --check
cargo check --workspace
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
```

涉及安全边界、安装、卸载、回滚、备份、并发的变更，不能只跑 `cargo check`。

## 计划中的 scripts 目录

建议脚本目录：

```text
scripts/
  verify.ps1
  check-policy.ps1
  check-file-size.ps1
  check-forbidden-files.ps1
  check-doc-links.ps1
  check-secrets.ps1
  check-governance-changes.ps1
  install-hooks.ps1
  build.ps1
  package.ps1
  release.ps1
```

### verify.ps1

本地统一验证入口。

职责：

- 执行文档检查。
- 执行策略检查。
- 执行前端检查。
- 执行 Rust 检查。
- 根据项目阶段自动跳过尚未落地的检查，并输出原因。

### check-policy.ps1

检查机器可读项目规则。

后续可读取：

```text
policy/project-policy.toml
```

可检查内容：

- 文件大小硬性干预线。
- 禁止提交的文件类型。
- 必须存在的文档。
- AGENTS.md 大小写。
- release 文档入口。

### check-file-size.ps1

检查文件行数、总字节数和可选的单行长度治理阈值。

它不应该简单地因为超过提醒线就失败。失败条件应对应 `CONTRIBUTING.md` 中的硬性干预线。
全局字节上限、文本单行上限和窄排除项由 `policy/project-policy.json` 定义；
lockfile 等特殊文件只能通过显式 allowlist 豁免。

### check-forbidden-files.ps1

禁止提交：

- 第三方 Mod 包。
- 真实存档。
- 本地缓存。
- 备份产物。
- token 或密钥文件。

### check-doc-links.ps1

检查 Markdown 内部链接是否有效。

至少应检查：

- README 文档入口。
- docs 目录下的相对链接。
- `AGENTS.md` 大小写。

### check-secrets.ps1

扫描受管文本中的明显敏感信息，包括治理 Python 脚本和 Rust/SQLite migration SQL。

注意：脚本只能降低风险，不能替代人工审查。

### check-governance-changes.ps1

检测治理文件是否被修改。

治理文件包括：

- `AGENTS.md`
- `CONTRIBUTING.md`
- `SECURITY.md`
- `docs/TESTING.md`
- `docs/release/`
- `policy/`
- `scripts/`
- `.githooks/`
- `.github/workflows/`

该脚本只提示人工 review，不阻止修改。

### install-hooks.ps1

安装本地 Git hooks：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\install-hooks.ps1
```

安装后会设置：

```text
git config core.hooksPath .githooks
```

### build.ps1

执行本地构建。

后续应包含：

- 前端 build。
- Rust check。
- Tauri build 的前置检查。

### package.ps1

执行本地打包。

后续应包含：

- 平台参数。
- 架构参数。
- 输出目录。
- 产物命名。
- 校验文件生成。

### Worker sidecar 准备

Windows 开发和 release 构建使用：

```powershell
cmd /c corepack pnpm run prepare:save-backup-worker-sidecar:dev
cmd /c corepack pnpm run prepare:save-backup-worker-sidecar
```

`scripts/prepare-save-backup-worker-sidecar.mjs` 从 `rustc -vV` 或受控 cross-target 环境解析 target triple，通过 `cargo metadata` 读取实际 target directory，构建 `hmm-save-backup-worker` 并复制到 Tauri external binary 命名。Windows 平台配置位于 `src-tauri/tauri.windows.conf.json`；base config 保持跨平台。

helper 内部 worker `cargo build` 会通过局部 `TAURI_CONFIG` merge patch 暂时清空 `bundle.externalBin`，避免 worker 尚未生成时触发 Tauri sidecar 存在性检查。该覆盖不进入正式 `tauri build`，正式 bundle 仍必须校验并包含 sidecar。`src-tauri/binaries/` 是生成目录，不得提交。

### release.ps1

发布辅助脚本。

后续应包含：

- 版本号检查。
- tag 检查。
- changelog / release notes 检查。
- 产物是否存在。
- 是否为 pre-release。

真实发布应优先由 GitHub Actions 完成，本地脚本只作为辅助。

## policy 目录

当前已经提供：

```text
policy/
  project-policy.json
```

用途：

- 将文档里的部分规则转成机器可读规则。
- 供本地脚本、Git hooks 和 CI 共同读取。
- 避免同一规则在多个脚本里重复硬编码。

当前使用 JSON 而不是 TOML，是为了让 PowerShell 脚本可以无额外依赖地解析策略文件。

## 计划中的 Git Hooks

当前已经提供：

```text
scripts/install-hooks.ps1
.githooks/pre-commit
.githooks/pre-push
```

建议检查：

- `git diff --check`
- 禁止文件类型
- 文件大小硬性干预线
- 文档链接
- secret 扫描

Git hooks 不是最终安全边界，因为它们可以被绕过。最终门禁应由 CI 完成。

## GitHub Actions

当前已经提供：

```text
.github/workflows/verify.yml
```

后续建议新增：

```text
.github/workflows/release.yml
```

### verify.yml

PR 和 main push 时执行：

- 文档检查。
- 策略检查。
- 前端 lint / build / test。
- Rust fmt / clippy / test。
- 禁止文件扫描。
- secret 扫描。

### release.yml

手动触发或 tag 触发：

- 检查版本号。
- 构建前端。
- 构建 Rust / Tauri。
- 生成平台产物。
- 生成校验文件。
- 创建 GitHub Release。

在没有稳定安装、卸载、回滚测试前，不应发布 Stable。

## 版本同步原则

后续需要保持以下位置版本一致：

- `package.json`
- `src-tauri/tauri.conf.json`
- Rust workspace crate version
- Release tag
- Release notes
- `CHANGELOG.md`

如果引入版本同步脚本，必须做到：

- 可预览变更。
- 不修改无关文件。
- 失败时不留下半更新状态。

## 产物目录约定

建议本地构建产物输出到：

```text
dist/
src-tauri/target/
release-artifacts/
```

这些目录不应提交到仓库。

## 当前状态

当前已实现 Tauri 工程、`package.json`、Rust workspace、验证脚本、policy、Git hooks 和 Windows worker sidecar 准备。仍未实现：

- GitHub Actions。
- 面向正式发布的一键打包/签名/校验脚本。
- NSIS/WiX owned Scheduled Task 自动卸载 cleanup。
- 一次性 Windows 账户/VM 中的安装态 sidecar 与 Scheduled Task runtime acceptance。

本地 `tauri build` 仍是开发验证入口，不等同于已通过签名、安装、卸载和 runtime smoke 的正式发布产物。
