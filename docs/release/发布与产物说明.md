# 发布与产物说明

本文档定义 Helsincy Mod Manager 的发布策略、平台支持等级和产物命名规则。当前项目仍处于脚手架前阶段，因此本文档是发布规划基线，具体构建产物会在 Tauri 工程落地后补充。

## 发布目标

第一阶段目标：

- Windows 为首发和主要支持平台。
- Linux 作为后续实验性平台。
- Steam Deck Desktop Mode 作为 Linux 实验性验证目标。
- macOS 暂不作为一等支持目标。

## 平台支持等级

### Tier 1：主要支持

Windows x64。

要求：

- 能安装和启动桌面应用。
- 能识别或手动选择 MHW:I 游戏目录。
- 能导入、校验、安装、卸载 Mod。
- 能备份和恢复测试存档目录。
- 能通过最小 smoke test。

### Tier 2：实验性支持

Linux x64。

要求：

- 能启动桌面应用。
- 能手动选择游戏目录。
- 能执行不依赖 Windows API 的核心功能。
- Steam library 扫描可逐步完善。

### Tier 3：社区验证

Steam Deck Desktop Mode。

要求：

- 通过社区测试反馈确认是否可用。
- 不在没有实机验证的情况下承诺稳定支持。
- 发布说明必须标注实验性状态。

## 发布类型

### Alpha

用于早期功能验证。

特点：

- 允许功能不完整。
- 允许 UI 尚未稳定。
- 必须避免破坏真实游戏目录和真实存档。
- 发布说明必须列出已知风险。

### Beta

用于接近完整工作流的验证。

特点：

- 主要功能应能串联。
- 必须有安装、卸载、回滚、备份的基础测试。
- 可以接受少量已知问题，但必须有规避说明。

### Stable

用于推荐普通玩家使用。

特点：

- 不应存在已知的误删、错误覆盖、错误恢复问题。
- 必须有明确的版本号、变更说明和回滚建议。
- 必须通过发布检查清单。

### Nightly / Preview

用于开发过程中的非正式验证。

特点：

- 可以由 CI 自动生成。
- 不保证稳定。
- 不建议普通玩家使用。
- 不应覆盖正式 Release 产物。

## 版本号规则

计划采用语义化版本：

```text
MAJOR.MINOR.PATCH
```

示例：

```text
0.1.0-alpha.1
0.2.0-beta.1
1.0.0
```

含义：

- `MAJOR`：破坏性变化或重大架构变化。
- `MINOR`：新增功能或较大行为变化。
- `PATCH`：修复问题、补充测试或文档修正。

在 `1.0.0` 前，`0.x` 版本允许更频繁调整接口和数据结构，但涉及安装清单、备份格式、数据库 migration 的变化必须写明兼容性。

## 预期产物命名

产物命名应包含：

- 应用名
- 版本号
- 平台
- 架构
- 渠道

示例：

```text
HelsincyModManager-0.1.0-alpha.1-windows-x64-setup.exe
HelsincyModManager-0.1.0-alpha.1-windows-x64-portable.zip
HelsincyModManager-0.1.0-alpha.1-linux-x64.AppImage
```

最终命名以 Tauri 打包能力和 CI 实现为准，但不应频繁变动。

## Release 附件策略

正式 Release 应至少包含：

- Windows 安装包。
- 校验文件。
- 变更说明。
- 已知问题。
- 升级和回退注意事项。

后续可选：

- Windows portable 包。
- Linux AppImage。
- SBOM。
- 签名文件。

不应上传：

- 第三方 Mod 包。
- 真实玩家存档。
- 本地配置文件。
- 含 token、cookie、API key 的日志。
- 未脱敏路径截图。

## 发布说明模板

发布说明至少包含：

```text
版本：
发布日期：
发布类型：
支持平台：

新增：
修复：
变更：
已知问题：
升级注意：
验证范围：
```

涉及安装、卸载、备份、回滚的版本，必须额外说明：

- 是否修改安装清单格式。
- 是否修改备份格式。
- 是否修改数据库 schema。
- 是否需要玩家重新扫描 Mod 库。

## 发版前检查清单

发版前至少确认：

- 工作区干净。
- 版本号已同步。
- README 和相关文档已更新。
- `docs/TESTING.md` 中对应范围的测试已执行。
- 没有提交真实 Mod 包、真实存档或敏感信息。
- 安装、卸载、回滚相关变更有测试或手动验证说明。
- Release notes 写明已知风险。
- 实验性平台明确标注实验性。

## Steam Deck 说明

Steam Deck 支持必须谨慎描述。

在没有实机验证前，只能写：

```text
Steam Deck Desktop Mode experimental / planned
```

不能写：

```text
Steam Deck fully supported
```

如果后续通过社区测试，也必须在 Release 说明中写明：

- SteamOS 版本。
- 测试者使用的安装方式。
- 游戏安装位置。
- 是否使用 SD 卡。
- 已知 UI 或权限问题。

## 当前状态

当前项目尚未创建 Tauri 工程，因此：

- 还没有可发布应用产物。
- 还没有正式打包脚本。
- 还没有 GitHub Actions 发布流程。
- 还没有平台签名策略。

这些内容会在项目脚手架和 CI 落地后更新。
