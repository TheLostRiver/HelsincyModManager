# Mod 库排序

排序入口位于 Mod 管理搜索框右侧。按钮显示当前字段和方向图标；紧凑浮层列出名称、导入时间、文件大小，
下方单独提供升序和降序两个选项，并保留“恢复默认”。选择字段后浮层保持打开，选择方向后关闭。
默认是最新导入；偏好保存在本机 WebView 的 `hmm.modLibrary.sort.v1` 中，独立于存档配置档。损坏或未知
偏好回退到默认值；存储不可用时仍允许在本次会话切换。

| 规则 | 查询值 | 含义 |
| --- | --- | --- |
| 最新导入（默认） | `imported_at_desc` | 首次加入 HMM 的时间从新到旧 |
| 最早导入 | `imported_at_asc` | 首次加入 HMM 的时间从旧到新 |
| 名称升序／降序 | `name_asc` / `name_desc` | 按用户当前看到的名称，包括名称覆盖 |
| 大小从大到小／从小到大 | `size_desc` / `size_asc` | 当前展示版本解包后的内容总字节数 |

## 数据口径

- revision 的可选 `ModRevisionStatistics` 保存导入时间和内容大小，JSON catalog v2 兼容缺失字段。
- 库条目的导入时间取 **origin revision**；追加版本、重新安装和重定向不修改首次导入时间。旧普通导入
  无可靠时间时保留未知，不使用文件 mtime、目录顺序或升级时间代替。旧外部导入可使用已持久化的来源时间。
- 大小取 **display revision**，包括包内自定义文件、说明和图片，排除 HMM 自己的缩略图缓存。它不是压缩
  归档大小、全部历史版本占用或已安装文件大小。安装配置中排除某个文件不会改变这份整包大小。
- ZIP、RAR 和 7z 由同一解包安全外壳返回实际写入的总字节数；不信任归档声明大小，不额外逐文件重读内容。
- 缺失的时间和大小在两个方向均排末尾。已知空包的 `0` 与未知值不同；前端不解析旧 `sizeLabel` 占位来
  推算数字。大小排序时，四种卡片视图显示格式化后的真实字节数，缺失时显示“大小未知”。

## 历史大小补齐

桌面启动后，由独立后台服务补齐当前展示版本缺少的大小。构造 runtime、CLI 查询、切换排序、挂载页面或
卡片不会启动扫描。每个桌面进程只执行一次，已有大小不重复扫描；只枚举受控包目录的常规文件并读取长度，
不读图片或 Mod 内容字节，不改变包文件。目录深度、条目数量、链接／reparse point 均受限制。

扫描期间不持有游戏写锁或目录写锁。写回时按 Mod、revision、package 三个身份重新匹配，只补缺失值；
条目被删除则跳过，已有统计不覆盖，展示版本不会被切回旧版本。JSON 使用既有原子保存和目录锁，SQLite
投影由既有 freshness guard 标为失效。包暂不可用或不安全时保持未知，不阻断库查询。

完成后，桌面发送无路径载荷的 `mod-library-statistics-updated` 失效事件；应用级缓存订阅使当前页重新查询。
订阅建立时也失效一次，覆盖后台任务先于前端完成的情况。无法测量的历史条目在下一次启动时仍可尝试补齐。

## 查询与顺序

生产查询始终执行“筛选 → 全库稳定排序 → 分页”。React 只提交排序值并渲染返回页，不拉取整个库或移动本地
文件。SQLite projection schema v3、migration 017 保存统计数字和名称排序键。五个复合索引覆盖名称双向、
时间双向与大小双向；普通查询和已安装状态查询都选择与规则匹配的索引。

名称先执行 NFKC、逐字符小写和空白归一化，再将数字段按有效位数和数字内容编码为二进制排序键，所以
`Mod 2` 排在 `Mod 10` 前。前导零不改变数字大小；其余字符按规范化后的 Unicode 顺序，不宣称拼音或读音
顺序。名称降序同时反转同名 ID 的顺序；时间和大小相同则按名称键、Mod ID 升序稳定打破平局。

库快照一次读取权威 catalog，避免 origin 与 display 来自不同读取。兼容仓储复用一次 analysis 映射，不为
每张卡片重复读取整库。筛选、总数、页码夹紧、标签和安装状态继续在同一投影 generation／读事务内完成。

## 交互与验证

选择新规则回到第一页和列表顶部，保留搜索、分类／状态筛选及每页容量。选择仍绑定 Mod ID，排序本身不清除
选择，也不重播视图切换动效；真正的库变更仍按既有选择失效规则处理。请求身份和有界会话缓存包含排序值，
快速切换的迟到响应不能覆盖新结果。浮层使用 portal、边界定位和键盘导航，适配深浅主题与最小原生窗口。

回归覆盖六种规则、Unicode／数字名、零与未知大小、同值顺序、搜索和筛选结合、跨页不重不漏、偏好持久化、
后台补齐与迟到响应。索引检查要求各方向无临时排序。既有 release 基准保留 1,000／10,000 条完整人工记录、
5 次预热和 40 次采样，10,000 条状态筛选查询的 p95 门槛仍为 14.23 ms，并对六种排序分别记录。
浏览器测试只证明交互与人工数据渲染，不能代替原生 IPC 或真实库验收。命令见 [测试指南](TESTING.md)。
